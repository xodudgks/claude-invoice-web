# 견적서 웹뷰어 개발 로드맵

노션에 입력한 견적서를 클라이언트가 로그인 없이 웹에서 확인하고 다운로드할 수 있게 한다.

## 개요

견적서 웹뷰어는 견적서를 발행하는 프리랜서/소규모 대행사(발행자)와 그 견적서를 받는 클라이언트(열람자)를 위한 서비스로 다음 기능을 제공합니다:

- **견적서 동기화(F001)**: 노션 데이터베이스에 입력된 견적서 데이터를 불러와 웹 서비스에 반영
- **견적서 상세 열람(F002)**: 클라이언트가 공유 링크로 접속해 품목/단가/수량/합계 등 견적 내용을 확인
- **견적서 다운로드(F003)**: 클라이언트가 웹에서 확인한 견적서를 파일로 다운로드
- **공유 링크 생성(F004)**: 발행자가 특정 견적서에 대한 고유 공유 링크를 생성하고 복사
- **기본 인증(F010)**: 발행자 회원가입/로그인/로그아웃
- **노션 연동 설정(F011)**: 발행자가 자신의 노션 데이터베이스와 연동하기 위한 정보를 등록

상세 요구사항은 [docs/PRD.md](./PRD.md) 참조.

## 개발 워크플로우

1. **작업 계획**
   - 기존 코드베이스를 학습하고 현재 상태를 파악
   - 새로운 작업을 포함하도록 `ROADMAP.md` 업데이트
   - 우선순위 작업은 마지막 완료된 작업 다음에 삽입

2. **작업 생성**
   - `/tasks` 디렉토리에 새 작업 파일 생성
   - 명명 형식: `XXX-description.md` (예: `001-setup.md`)
   - 고수준 명세서, 관련 파일, 수락 기준, 구현 단계 포함
   - **API/비즈니스 로직 작업 시 "## 테스트 체크리스트" 섹션 필수 포함 (Playwright MCP 테스트 시나리오 작성)**

3. **작업 구현**
   - 작업 파일의 명세서를 따름
   - **API 연동 및 비즈니스 로직 구현 시 Playwright MCP로 테스트 수행 필수**
   - 각 단계 후 작업 파일 내 단계 진행 상황 업데이트
   - 테스트 통과 확인 후 다음 단계로 진행
   - 각 단계 완료 후 중단하고 추가 지시를 기다림

4. **로드맵 업데이트**
   - 로드맵에서 완료된 작업을 ✅로 표시

## 개발 단계

### Phase 1: 애플리케이션 골격 구축

- **Task 001: 프로젝트 라우트 구조 및 레이아웃 설정** - 우선순위
  - App Router 라우트 생성: `/login`, `/signup`, `/dashboard`, `/settings/notion`(노션 연동 설정), `/s/[shareToken]`(견적서 공유 페이지)
  - 인증 필요 라우트 그룹((dashboard))과 비로그인 라우트 그룹((auth)), 공유 페이지 라우트를 분리
  - 발행자용 공통 레이아웃(헤더 내비 - 대시보드/노션 연동 설정/로그아웃)과 공유 페이지 전용 레이아웃(내비 없음) 구현
  - 각 페이지의 빈 껍데기 컴포넌트 생성 및 라우팅 동작 확인

- **Task 002: 타입 정의 및 데이터 모델 설계**
  - PRD 데이터 모델 기준 `User`, `Estimate`, `EstimateItem` TypeScript 인터페이스 정의
  - Supabase 테이블 스키마 초안 설계 (User/Estimate/EstimateItem 및 관계, 실제 마이그레이션 적용은 제외)
  - 공유 링크(`shareToken`) 및 API 응답 타입 정의
  - 로그인/회원가입/노션 연동 폼용 Zod 스키마 초안 작성

### Phase 2: UI/UX 완성 (더미 데이터 활용)

- **Task 003: 인증 페이지 UI 구현**
  - 로그인/회원가입 폼 UI (`Field`/`FieldLabel`/`FieldError` + `Controller` + Zod 조합, `src/components/examples/profile-form-example.tsx` 패턴 참고)
  - 이메일/비밀번호(회원가입 시 이름 포함) 입력 유효성 검사 및 에러 메시지 표시
  - 로그인 ↔ 회원가입 페이지 간 이동 링크
  - 반응형 대응 및 모바일 최적화

- **Task 004: 대시보드 및 노션 연동 설정 페이지 UI 구현 (더미 데이터)**
  - 견적서 목록 UI (견적명, 클라이언트명, 합계 금액) - 하드코딩된 더미 데이터 사용
  - 노션 데이터 동기화 버튼, 견적서별 공유 링크 생성/복사 버튼 UI (동작은 모킹)
  - 노션 미연동 상태 안내 배너 → 연동 설정 페이지 이동 UI
  - 노션 연동 정보 입력 폼 UI 및 연동 상태(연동됨/미연동) 표시

- **Task 005: 견적서 공유 페이지 UI 구현 (더미 데이터)**
  - 견적서 기본 정보(견적명, 발행자, 클라이언트명, 발행일) 표시 영역
  - 품목/단가/수량/소계/합계 테이블 UI - 더미 데이터 사용
  - 다운로드 버튼 UI (동작은 모킹)
  - 유효하지 않은 공유 링크 접근 시 안내 화면

### Phase 3: 핵심 기능 구현

- **Task 006: Supabase 인증 연동 (F010)** - 우선순위
  - Supabase 프로젝트 설정 및 Auth 연동
  - 회원가입/로그인/로그아웃 API 및 폼 제출 로직 구현
  - 세션 기반 라우트 보호 미들웨어 ((dashboard) 그룹 접근 제어)
  - Playwright MCP로 회원가입 → 로그인 → 로그아웃 E2E 테스트 수행

- **Task 007: 노션 연동 설정 기능 구현 (F011)**
  - 노션 연동 키/데이터베이스 ID를 `User`에 저장하는 API 구현
  - 저장 전 노션 API 호출을 통한 연동 정보 유효성 검사
  - 연동 상태(연동됨/미연동) 실데이터 반영
  - Playwright MCP로 연동 설정 성공/실패 플로우 테스트

- **Task 008: 견적서 동기화 기능 구현 (F001)**
  - Notion API로 발행자의 데이터베이스에서 견적서 데이터 조회
  - `Estimate`/`EstimateItem` 매핑 및 Supabase 저장, `syncedAt` 갱신
  - 대시보드 동기화 버튼을 실제 API 호출로 교체, 견적서 목록 실데이터 반영
  - Playwright MCP로 동기화 성공/실패(미연동 상태) 시나리오 테스트

- **Task 009: 공유 링크 생성 기능 구현 (F004)**
  - 견적서별 고유 `shareToken` 생성 로직 구현
  - 대시보드의 공유 링크 생성/복사 버튼을 실제 동작으로 교체
  - Playwright MCP로 링크 생성 및 클립보드 복사 테스트

- **Task 010: 견적서 상세 열람 및 다운로드 기능 구현 (F002, F003)**
  - `shareToken` 기반 공개 조회 API 구현 (인증 불필요)
  - 견적서 다운로드 파일 생성 및 다운로드 기능 구현
  - 유효하지 않거나 존재하지 않는 토큰 접근 시 에러 안내 처리
  - Playwright MCP로 정상 열람/다운로드 및 잘못된 링크 접근 테스트

- **Task 010-1: 핵심 기능 통합 테스트**
  - Playwright MCP로 발행자 전체 플로우 E2E 테스트 (회원가입 → 로그인 → 노션 연동 → 동기화 → 공유 링크 생성)
  - Playwright MCP로 열람자 전체 플로우 E2E 테스트 (공유 링크 접속 → 견적 확인 → 다운로드)
  - API 연동 및 비즈니스 로직 검증, 에러 핸들링/엣지 케이스(미연동, 동기화 실패, 무효 토큰 등) 테스트

### Phase 4: 고급 기능 및 최적화

- **Task 011: 사용자 경험 향상**
  - 로딩 상태/스켈레톤 UI, 토스트 알림(`src/components/ui/sonner.tsx`) 적용
  - 빈 상태(견적서 없음, 미연동 등) UI 다듬기
  - 다크모드 대응 점검

- **Task 012: 성능 최적화 및 배포**
  - 견적서 목록/공유 페이지 캐싱 전략 적용
  - Vercel 배포 파이프라인 구성 및 환경 변수(Supabase, Notion API 키 등) 설정
  - 기본 모니터링 및 에러 로깅 구성
