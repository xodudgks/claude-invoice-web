# MVP PRD 작성용 메타 프롬프트

노션(Notion)에 입력한 견적서 데이터를 클라이언트가 웹에서 확인하고 PDF로 다운로드할 수 있는
서비스의 MVP PRD(Product Requirements Document)를 생성하기 위한 메타 프롬프트입니다.

아래 프롬프트를 그대로 복사해 Claude(또는 다른 LLM)에 입력하면 PRD 문서 초안이 산출됩니다.

---

## 사용 방법

1. `[서비스명 입력]` 부분을 실제 서비스명으로 교체합니다.
2. 노션 API 인증 방식, 커스텀 도메인 지원 여부 등 이미 결정된 사항이 있다면
   "결정된 사항" 섹션을 프롬프트 상단에 추가로 붙여 넣습니다. (결정되지 않은 부분은
   AI가 "결정 필요" 항목으로 명시하도록 설계되어 있습니다.)
3. 산출된 PRD를 바탕으로 구현 계획이 필요하면 Plan 모드 또는 `/plan`으로 이어서 진행합니다.

---

## 메타 프롬프트

```
당신은 10년 경력의 시니어 프로덕트 매니저입니다.
아래 서비스에 대한 MVP PRD(Product Requirements Document)를 작성해주세요.

# 서비스 개요
- 서비스명: [Notion WEB]
- 한 줄 설명: 노션(Notion)에 입력한 견적서 데이터를 기반으로, 클라이언트가 별도 로그인 없이
  웹 페이지에서 견적 내용을 확인하고 PDF로 다운로드할 수 있는 서비스
- 핵심 사용자: 프리랜서/소규모 대행사(견적서 발행자), 그들의 클라이언트(견적서 열람자)

# 배경 및 문제 정의
- 기존에는 견적서를 엑셀/한글/PDF로 만들어 이메일이나 메신저로 전달함
- 문제점:
  1. 수정 발생 시 파일을 재전송해야 하고 버전 관리가 안 됨
  2. 클라이언트가 견적서를 열람했는지 확인 불가
  3. 디자인 및 포맷이 매번 수작업으로 들어감
- 노션을 이미 업무 툴로 쓰고 있어, 노션에 입력만 하면 자동으로 웹 링크/PDF가 생성되길 원함

# 요청 사항
다음 항목을 포함한 PRD를 작성하세요. 각 항목은 구체적이고 실행 가능한 수준으로 작성하고,
불확실하거나 결정이 필요한 부분은 "결정 필요" 항목으로 명시하세요.

1. **목표(Goal) & 성공 지표(KPI)**
   - MVP가 달성해야 하는 핵심 목표 1~2개
   - 정량적으로 측정 가능한 성공 지표 (예: 견적서 발행~열람 소요 시간, PDF 다운로드율 등)

2. **범위 정의 (In Scope / Out of Scope)**
   - MVP에 반드시 포함할 기능
   - 이번 MVP에서 명시적으로 제외할 기능 (향후 로드맵으로 분리)

3. **핵심 사용자 플로우**
   - 발행자: 노션에 견적 데이터 입력 → 웹 링크 생성 → 클라이언트 공유
   - 열람자: 링크 접속 → 웹에서 견적 내용 확인 → PDF 다운로드
   - 각 단계별 화면/상태를 텍스트로 순서도처럼 서술

4. **기능 명세 (Feature Spec)**
   - 기능명 / 설명 / 우선순위(P0/P1/P2) / 완료 조건(Acceptance Criteria) 표 형태로 작성
   - 특히 아래 항목은 반드시 다룰 것:
     a. 노션 → 웹 데이터 동기화 방식 (Notion API, Webhook, 수동 새로고침 등 옵션 비교)
     b. 웹 페이지 접근 권한 (공개 링크 vs 비밀번호 vs 만료 기한)
     c. PDF 생성 방식 (서버 렌더링 vs 클라이언트 렌더링, 라이브러리 후보)
     d. 견적서 데이터 구조 (품목, 단가, 수량, 합계, 세금, 유효기간 등 필드 정의)

5. **데이터 모델 (초안)**
   - 노션 데이터베이스 스키마 초안 (속성명, 타입)
   - 웹/서버에서 사용할 데이터 모델과의 매핑 관계

6. **비기능 요구사항**
   - 성능 (PDF 생성 응답 시간 목표치)
   - 보안 (견적 링크 유출 시 리스크 및 완화 방안)
   - 모바일 대응 여부

7. **기술적 제약 및 의사결정 필요 항목**
   - Notion API 요율 제한, 인증 방식 등 확인이 필요한 부분
   - "결정 필요"로 남겨야 하는 항목 리스트업 (예: 유료 플랜 여부, 커스텀 도메인 지원 여부)

8. **마일스톤 및 우선순위**
   - MVP 출시까지 필요한 최소 작업 단위를 우선순위 순으로 나열
   - 각 마일스톤의 완료 기준

9. **리스크 및 오픈 이슈**
   - 예상되는 리스크 (예: Notion API 변경, 대용량 견적서의 PDF 렌더링 실패 등)
   - 아직 결정되지 않은 오픈 이슈 목록

# 출력 형식
- 마크다운 형식
- 표는 마크다운 테이블 사용
- 전체 분량은 A4 기준 3~5페이지 수준으로 간결하게 작성
- 전문 용어 사용 시 괄호로 짧은 설명 병기
- 모든 문서는 한국어로 작성
```
